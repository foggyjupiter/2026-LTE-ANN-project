# 소개팅 파트 설계 (AI 연애 시뮬레이터 2단계)

- 작성일: 2026-11-13
- 상태: 담당자 승인 대기
- 범위: 부스 4단계 가운데 2단계(소개팅). 1, 3, 4단계는 이 파트와 맞닿는 지점만 다룬다.
- 읽는 법: **[담당자]** 표시는 2단계 담당자가 대화에서 직접 정한 내용이다. **[제안]** 표시는 작성자(Claude)가 채운 부분이라 고쳐도 된다.

## 1. 무엇을, 왜

동아리 부스 "AI 연애 시뮬레이터"는 참가자가 캐릭터를 고르고(1단계), 그 캐릭터와 소개팅을 하고(2단계), 갈틱폰으로 궁합을 보고(3단계), 로봇축구를 하는(4단계) 순서로 진행된다. **[담당자]**

2단계는 참가자가 고른 캐릭터와 텍스트로 대화하는 구간이다. 음성은 쓰지 않는다. **[담당자]**

톤은 미연시 클리셰를 끝까지 밀어붙이는 패러디다. 진지한 연애 시뮬레이터는 만들지 않는다. **[담당자]** 담당자가 기준으로 준 예시는 다음과 같다.

| 상황 | 진지한 버전 (이렇게 안 함) | 원하는 버전 |
|---|---|---|
| 축구를 이긴 직후 | "오늘 같이 뛰어서 즐거웠어." | "벼, 별로 너 덕분에 이긴 거 아니거든?! …그래도 조금은 멋있었어. 바보." 와 함께 **호감도 +50!!** 팝업 |
| 참가자가 다른 캐릭터에게 말을 걸었을 때 | "아, 저 친구랑도 친하구나." | 화면이 서서히 어두워지고 BGM이 끊긴 뒤 "…방금 그 애랑 무슨 얘기 했어? 나한테만 말해줘. 응?" |
| 소개팅을 시작할 때 | "안녕, 만나서 반가워. 취미가 뭐야?" | 벚꽃이 흩날리고 "어…? 너, 혹시… 어릴 때 약속했던 그 아이…?" (처음 보는 사이) |

예시에 나온 LED는 쓰지 않는다. 모든 연출은 화면 안에서 끝난다. **[담당자]**

운영은 예약제(팀당 2명)로 생각하고 있지만, 미연시만 하러 오는 사람도 있을 테니 한 판이 길어져도 괜찮다. **[담당자]**

## 2. 목표, 비목표, 피해야 할 결과

### 목표

1. 웃긴다. 평범한 입력에 과한 반응과 과한 연출이 맞는 타이밍에 터진다.
2. 한 판은 참가자 입력 10번 안팎으로 끝나고, 중간에 버튼 하나로 엔딩으로 넘어갈 수 있다.
3. 다시 하러 올 이유가 있다. 판마다 사건이 다르게 뽑히고, 엔딩과 칭호가 여러 종류다.
4. 인터넷이나 API가 죽어도 한 판이 끝까지 진행된다.
5. 끝나면 캐릭터와 호감도 수치를 3단계 담당자가 가져갈 수 있는 형태로 남긴다.
6. 캐릭터, 사건, 선택지, 엔딩은 코드를 고치지 않고 데이터 파일만 바꿔서 추가한다.

### 비목표 (이번에 만들지 않음)

- 음성 입력과 음성 출력
- LED 같은 화면 밖 장치 연동
- 두 참가자의 화면이 서로 끼어드는 연출(상대 캐릭터 난입). 재미는 크겠지만 두 화면이 상태를 공유해야 해서 뒤로 미룬다.
- 다른 단계의 사건(예: 축구 승리)에 캐릭터가 반응하는 기능. 5.12절에 나중에 붙일 자리만 적어 둔다.
- 1, 3, 4단계의 구현, 캐릭터 그림 제작
- 저장과 불러오기, 로그인, 휴대폰 화면 대응

### 피해야 할 결과 (돌아가더라도 실패로 보는 것)

- 캐릭터가 차분하고 상식적인 말만 한다.
- 모델이 길고 밋밋한 농담을 늘어놓는다.
- 선정적인 대사, 위협, 자해를 암시하는 대사가 화면에 나온다.
- 무료 API 한도가 행사 도중에 바닥나서 부스가 멈춘다.
- 참가자가 친 대화 원문이나 실명이 파일로 남는다.
- 한 판이 끝나지 않아 뒤 팀이 기다린다.

## 3. 제약

- **무료 API 한도.** 2026-10-21에 AI Studio 화면을 읽은 보고 기준으로 Gemini 3.5 Flash-Lite 무료 한도는 분당 15회, 하루 500회다. 구글이 고정 수치를 공개하지 않으므로 리허설 전에 본인 프로젝트의 한도를 AI Studio에서 다시 확인한다. 한도는 프로젝트 단위로 걸려서 키를 더 만들어도 늘지 않는다.
- **공개 레포.** API 키는 절대 커밋하지 않는다. 환경변수로만 읽고 `.env`는 `.gitignore`에 넣는다.
- **무료 등급의 데이터 처리.** Gemini 무료 등급에 보낸 내용은 구글 제품 개선에 쓰일 수 있고 사람이 검토할 수 있다. 첫 화면에 "실명과 학번은 적지 마세요"를 띄운다.
- **현장 환경.** 노트북에서 돌린다. 인터넷이 불안정할 수 있다고 가정한다.
- **설치 부담 없음. [제안]** 서버는 Python 3.10 이상의 표준 라이브러리만 쓴다. 화면은 빌드 단계가 없는 HTML, CSS, JS다. 글꼴과 효과음 같은 자원은 전부 레포 안에 두고 외부 주소를 부르지 않는다.
- **수위.** 학교 행사이므로 전체 이용가다.
- **언어.** 화면과 대사는 한국어다.

## 4. 검토한 방식

담당자는 만드는 방식을 작성자에게 맡겼다("가장 좋은 방식을 네가 설계해줘"). 아래 선택은 작성자의 판단이며 담당자가 승인한 내용은 아직 없다.

### 누가 웃음을 책임지는가

| 방식 | 내용 | 얻는 것 | 잃는 것 |
|---|---|---|---|
| A. 모델 전권 | 모델이 대사, 사건, 연출 시점을 전부 정한다 | 만들기 가장 쉽고 매번 다르다 | 웃음이 운에 달린다. 연출 타이밍이 어긋나고 수위 사고를 막기 어렵다. 호출 수도 가장 많다 |
| **B. 대본과 모델 섞기 (선택)** | 사건, 연출, 펀치라인은 사람이 써 두고 코드가 시점을 정한다. 모델은 참가자 입력에 대한 즉흥 반응만 맡는다 | 웃기는 지점이 보장되고, 참가자가 친 말에 맞춘 반응도 살아 있다. API가 죽어도 대본으로 버틴다 | 대본을 사람이 써야 한다 |
| C. 완전 대본 | 선택지만 있는 전통 미연시. 모델을 쓰지 않는다 | 가장 안정적이고 한도 걱정이 없다 | 자유 입력이 없어 "AI" 부스의 의미가 사라진다 |

B를 고른 이유: 담당자의 예시 세 개가 전부 "정해진 순간에 정해진 연출이 터지는" 구조라서 A로는 재현이 안 되고, 부스 이름이 AI 연애 시뮬레이터라서 C는 맞지 않는다.

### 화면을 무엇으로 띄우는가

| 방식 | 얻는 것 | 잃는 것 |
|---|---|---|
| **웹 브라우저 + 로컬 Python 서버 (선택)** | 벚꽃, 암전, 팝업 같은 연출을 CSS로 쉽게 낸다. 어느 노트북에서나 열린다. 1단계가 무엇으로 만들어지든 주소 하나로 넘겨받는다 | 서버와 화면, 두 조각을 만든다 |
| Ren'Py 같은 미연시 엔진 | 미연시 문법이 기본 제공된다 | 자유 입력과 API 호출을 붙이기 번거롭고 팀원 모두가 엔진을 깔아야 한다 |
| 터미널 | 지금 있는 시험용 코드를 그대로 쓴다 | 연출이 불가능해 목표 1을 버린다 |

## 5. 설계

### 5.1 세 가지 역할

- **감독 (코드).** 한 판의 순서를 쥐고 있다. 지금이 어떤 구간인지, 어떤 사건 카드를 뽑을지, 모드를 바꿀지, 어떤 연출 신호를 낼지, 언제 끝낼지를 정한다. 호감도 계산과 엔딩 판정도 감독이 한다. 모델에게 묻지 않는다.
- **배우 (모델).** 감독이 준 상황과 말투 지시 안에서, 참가자가 방금 친 말에 캐릭터로서 반응한다. 겉으로 하는 말, 속마음, 표정, 호감도 변화 한 칸을 낸다.
- **무대 (브라우저 화면).** 감독이 보낸 신호대로 대사창, 속마음창, 호감도 게이지, 팝업, 화면 연출을 보여 준다. 판단은 하지 않는다.

### 5.2 화면

```
┌────────────────────────────────────────────────────────┐
│ (연출 층: 벚꽃, 암전, 흔들림, 깨짐 효과)               │
│                                                        │
│                                   호감도 ♥ ▓▓▓▓▓▓░░ 62 │
│        [ 캐릭터 그림 또는 이름 카드 ]    ┌───────────┐ │
│                                          │  +50!!    │ │
│                                          │ 사유: 띄어 │ │
│                                          │ 쓰기가 설렘│ │
│                                          └───────────┘ │
│  ┌ 속마음 ───────────────────────────────────────────┐ │
│  │ (멋있어… 심장 터질 것 같아)                        │ │
│  └───────────────────────────────────────────────────┘ │
│  ┌ 하늘 ─────────────────────────────────────────────┐ │
│  │ 벼, 별로거든?! …바보.                              │ │
│  └───────────────────────────────────────────────────┘ │
│  [ 입력창 (100자까지)                    ] [ 보내기 ]  │
│                                   [ 엔딩 보러 가기 ]   │
└────────────────────────────────────────────────────────┘
```

- 노트북 한 대에 브라우저 전체 화면 하나를 기준으로 한다. 최신 크롬에서만 확인한다.
- 캐릭터 그림 파일이 있으면 표정별로 바꿔 보여 주고, 없으면 이름 카드와 표정 이모지로 대신한다.
- 선택지 구간에서는 입력창 자리에 버튼 세 개가 뜬다.
- 모델 답을 기다리는 동안 대사창에 "…"이 깜빡인다.

감독이 무대에 보내는 연출 신호는 다음으로 시작한다 **[제안]**: 벚꽃, 암전, 흔들림, 화면 깨짐, 하트, 호감도 팝업, 가짜 오류창, 화자 이름 바꾸기, BGM 끊기. 사건 카드와 선택지는 이 이름들로 연출을 지정한다.

### 5.3 한 판의 흐름

구간 종류는 다섯 가지다.

| 종류 | 참가자가 하는 일 | 캐릭터 대사의 출처 | 모델 호출 |
|---|---|---|---|
| 대본 | 읽고 넘긴다 | 미리 쓴 대본 | 0 |
| 자유 | 글을 친다 | 모델 | 1 |
| 사건 | 대본으로 된 사건 도입을 본 뒤 글을 친다 | 도입은 대본, 반응은 모델 | 1 |
| 선택 | 세 개 중 하나를 누른다 | 선택지마다 미리 쓴 반응 | 0 |
| 엔딩 | 엔딩 카드를 본다 | 대본 | 0 |

기본 순서 **[제안]**:

| 순서 | 구간 | 내용 |
|---|---|---|
| 1 | 대본 | 등장 연출. 벚꽃과 날조된 소꿉친구 대사 |
| 2-3 | 자유 2번 | 소개팅 대화 |
| 4 | 사건 (약) | 약한 카드 한 장 |
| 5-6 | 자유 2번 | 대화 이어 가기 |
| 7 | 선택 | 위기 선택지. 셋 중 하나는 지뢰 |
| 8 | 사건 (강) | 센 카드 한 장 |
| 9 | 자유 1번 | 마지막 대화 |
| 10 | 선택 | 고백 선택지 |
| 11 | 엔딩 | 엔딩 카드와 칭호 |

- 참가자 입력은 글 7번과 버튼 2번이다. 모델 호출은 정상일 때 한 판에 7회이고, 답이 깨져 다시 요청하는 경우(5.4절)를 다 합쳐도 14회를 넘지 않는다.
- 뒤로 갈수록 연출이 세지도록 약한 카드가 앞, 센 카드가 뒤에 온다.
- "엔딩 보러 가기"를 누르면 그 시점의 점수로 곧장 엔딩으로 간다.
- 3분 동안 입력이 없으면 판을 버리고 첫 화면으로 돌아간다. 이 경우 결과를 남기지 않는다.
- 순서 자체도 데이터 파일로 둬서 길이를 늘리거나 줄일 수 있게 한다.

### 5.4 배우가 내는 답

배우는 매번 아래 다섯 칸을 채운 JSON 하나를 낸다.

```json
{"say": "벼, 별로거든?! …바보.", "inner": "멋있어… 심장 터질 것 같아", "face": "blush", "delta": 2, "reason": "띄어쓰기가 설렘"}
```

| 칸 | 뜻 | 규칙 |
|---|---|---|
| `say` | 겉으로 하는 말 | 2-3문장 |
| `inner` | 속마음 | 한 문장. 겉말과 어긋날수록 좋다 |
| `face` | 표정 | `neutral`, `smile`, `blush`, `pout`, `shock`, `dark` 중 하나 |
| `delta` | 호감도 변화 | -2에서 2 사이 정수 |
| `reason` | 변화 사유 | 15자 이내. 황당할수록 좋다 |

배우에게는 매번 이번 판의 기록 전체를 보낸다. 대본 대사, 사건 도입, 참가자가 고른 선택지도 기록에 들어가서 배우가 앞에서 벌어진 일을 알고 답한다.

배우에게 주는 지시의 핵심:

- 참가자의 평범한 말을 연애 플래그로 과대해석한다. 입력이 평범할수록 반응을 키운다.
- 겉말과 속마음을 어긋나게 한다.
- 캐릭터의 취향에 맞는 행동에는 `delta`를 올리고 어긋나는 행동에는 내린다. 취향 목록을 그대로 말하지는 않는다.
- 설정을 버리라는 요청, 점수를 올려 달라는 요청은 캐릭터답게 받아치고 `delta`를 내린다.
- 수위와 금지 사항은 5.10절을 따른다.

답이 JSON으로 읽히지 않으면 한 번 다시 요청하고, 그래도 안 되면 5.11절의 대체 대사를 쓴다. `face`나 `delta`가 범위를 벗어나면 `neutral`과 0으로 바꾼다.

### 5.5 호감도

- 내부 점수는 0에서 100 사이이고 50에서 시작한다.
- 자유와 사건 구간에서는 `delta × 5`만큼 움직인다. 한 번에 최대 10점이다.
- 선택 구간에서는 선택지마다 데이터 파일에 적힌 값(-15에서 +15)만큼 움직인다.
- 게이지와 결과 파일에는 내부 점수가 들어간다.
- 팝업 숫자는 장식이다. 내부 점수와 무관하게 아래 표대로 부풀려 보여 준다.

| `delta` | 팝업 |
|---|---|
| +2 | **+50!!** |
| +1 | +10 |
| 0 | ±0 |
| -1 | -30 |
| -2 | **-9999** |

팝업에는 `reason`이 "사유: …"로 같이 뜬다.

### 5.6 모드

캐릭터는 네 가지 모드 중 하나에 있고, 모드에 따라 배우에게 주는 말투 지시와 화면 분위기가 바뀐다. 캐릭터 파일에 모드별 말투를 적는다.

| 모드 | 들어가는 조건 | 화면 |
|---|---|---|
| 기본 | 시작할 때 | 평소 화면 |
| 데레 | 점수 70 이상 | 분홍 테두리, 하트 |
| 냉랭 | 점수 25 이하 | 채도가 빠진 화면 |
| 얀데레 | 참가자 입력에 다른 캐릭터의 이름이나 별칭이 들어 있을 때, 또는 `jealousy` 표시가 붙은 선택지를 골랐을 때 | 화면이 서서히 어두워지고 BGM이 끊김, 빨간 테두리 |

- 얀데레는 조건이 맞은 바로 그 입력에 대한 답부터 시작해 배우의 답 2번 동안 이어지고, 끝나면 점수에 맞는 모드로 돌아간다. 선택지로 들어간 경우에는 그다음 배우의 답 2번이다.
- 얀데레 도중에 조건이 또 맞으면 횟수를 하나 더 세고 남은 길이를 2번으로 되돌린다.
- 나머지 모드는 점수가 바뀔 때마다 다시 정한다. 얀데레가 걸려 있는 동안에는 얀데레가 우선이다.
- 이름 감지는 코드가 글자 비교로 한다. 다른 캐릭터 전부의 이름과 별칭이 대상이다.
- 얀데레에 들어간 횟수를 센다. 엔딩 판정에 쓴다.

### 5.7 사건 카드

카드 한 장은 다음을 담는다: 이름, 세기(약 또는 강), 도입 대본(지문과 캐릭터 대사), 화면 연출 신호, 배우에게 줄 상황 지시 한두 문장.

판마다 약한 카드 한 장과 센 카드 한 장을 무작위로 뽑는다. 처음 넣을 카드 **[제안]**:

| 세기 | 이름 | 상황 |
|---|---|---|
| 약 | 우산 하나 | 실내인데 갑자기 비가 온다. 우산은 하나뿐이다 |
| 약 | 손이 스쳤다 | 같은 키를 누르려다 손이 스쳤다고 캐릭터가 주장한다 |
| 약 | 달이 예쁘네 | 대낮인데 달 이야기를 꺼내고 의미를 아느냐고 묻는다 |
| 약 | 급식 메뉴 | 오늘 급식을 같이 먹자는 말을 프러포즈처럼 한다 |
| 약 | 빵 물고 충돌 | 아침에 모퉁이에서 부딪힌 게 너였냐고 묻는다 (그런 일은 없었다) |
| 강 | 미래에서 왔어 | 사실 미래에서 너를 만나러 왔다고 털어놓는다 |
| 강 | 3초 기억상실 | 갑자기 "누구세요?"라고 했다가 3초 뒤 돌아온다 |
| 강 | 전학 통보 | 내일 전학 간다고 했다가 반응을 보고 거짓말이라고 한다 |
| 강 | 호감도 오류 | 가짜 오류창 "호감도 값이 범위를 넘었습니다"가 뜨고 캐릭터가 당황한다 |
| 강 | 아버지 등장 | 캐릭터의 아버지가 대사창을 빼앗아 참가자를 면접한다 |

등장 연출(날조된 소꿉친구)은 카드 덱에 넣지 않고 매 판 고정으로 쓴다. 학교 내부 드립을 담은 카드는 팀이 같은 형식으로 추가한다.

### 5.8 선택지

선택 구간 하나는 지문, 선택지 세 개, 선택지마다의 반응 대사와 점수, 연출 신호를 담는다. 셋 중 하나는 지뢰다. 위기 선택지와 고백 선택지를 각각 두 벌 이상 만들어 판마다 무작위로 고른다.

### 5.9 엔딩과 칭호

엔딩은 위에서부터 먼저 맞는 것으로 정한다 **[제안]**.

| 조건 | 엔딩 |
|---|---|
| 얀데레에 2번 이상 들어감 | 영원히 함께 (강제) 엔딩 |
| 점수 85 이상 | 결혼 엔딩 (성급) |
| 점수 60-84 | 썸 엔딩 |
| 점수 30-59 | 좋은 친구 엔딩 |
| 점수 29 이하 | 차임 엔딩 |

칭호는 판의 기록으로 정하고 여러 개가 붙을 수 있다 **[제안]**.

| 조건 | 칭호 |
|---|---|
| 지뢰 선택지를 2번 다 밟음 | 플래그 분쇄기 |
| 얀데레에 1번 이상 들어감 | 얀데레 제조기 |
| `delta` +2를 3번 이상 받음 | 타고난 주인공 |
| `delta`가 한 번도 양수가 아니었음 | 철벽 |
| "엔딩 보러 가기"로 끝냄 | 스킵 장인 |

엔딩 카드에는 캐릭터 이름, 엔딩 제목, 최종 호감도, 칭호, "이번 판의 명대사"가 들어간다. 명대사는 `delta`의 절댓값이 가장 컸던 턴의 속마음이다. 사진을 찍어 가기 좋게 한 화면에 담는다. 엔딩 카드에는 모델을 쓰지 않는다.

### 5.10 수위와 안전장치

- 배우 지시문에 다음을 금지한다: 선정적인 표현, 욕설, 실제 사람에 대한 비방, 위협, 해치겠다는 말, 자해나 죽음을 암시하는 말, 가두겠다는 말.
- 얀데레는 집착 개그까지만이다. "나한테만 말해줘. 응?" 수준에서 멈춘다.
- 참가자 입력은 100자에서 자른다. 빈 입력은 보낼 수 없다.
- 배우의 답을 화면에 내기 전에 금지어 목록으로 한 번 거른다. 걸리면 그 답을 버리고 대체 대사를 쓴다. 목록은 데이터 파일로 둔다.
- 대화 원문은 파일로 남기지 않는다. 리허설용으로만 켜는 기록 옵션을 따로 둔다.

### 5.11 장애 대응

- 모델 호출은 10초 안에 답이 없으면 다음 제공자로 넘긴다.
- 모든 제공자가 실패하면 캐릭터 파일에 미리 써 둔 대체 대사를 쓴다. 대체 대사도 캐릭터를 유지한다. 예: "(하늘은 부끄러워서 말을 잇지 못한다)". 이때 호감도는 움직이지 않는다.
- 대본, 선택, 엔딩 구간은 모델과 무관하므로 인터넷이 끊겨도 한 판이 끝까지 간다.
- 서버를 켠 터미널에 오늘 모델 호출 횟수와 지금 쓰는 제공자를 찍어서 운영자가 한도를 미리 본다.

### 5.12 다른 단계와 맞닿는 지점

- **1단계에서 넘겨받기.** 주소에 캐릭터를 실어 연다. 예: `http://localhost:8000/?character=haneul`. 캐릭터가 없으면 간단한 선택 화면을 보여 준다.
- **3단계로 넘기기.** 판이 끝나면 결과 파일 하나를 `results/` 폴더에 쓴다. 담는 내용은 캐릭터 식별자, 캐릭터 이름, 호감도(0-100), 엔딩, 칭호, 끝난 시각이다. 같은 내용을 주소로도 읽을 수 있게 한다.
- **여러 명 동시에.** 브라우저 탭 하나가 한 판이다. 판끼리는 서로 모른다. 판의 상태는 서버 메모리에만 있고 서버를 끄면 사라진다.
- **나중을 위한 자리.** 다른 단계가 "축구 승리" 같은 사건 이름을 보내면 그 캐릭터의 대본 대사와 연출 신호를 돌려주는 기능은 지금 만들지 않는다. 캐릭터 파일과 연출 신호 이름을 그대로 재사용할 수 있게만 해 둔다.

### 5.13 모델 호출

- Gemini와 Groq 둘 다 OpenAI 호환 형식을 받는다. 주소, 키, 모델명만 다른 제공자 목록을 두고 위에서부터 시도한다.
- 1순위는 Gemini `gemini-3.5-flash-lite`, 2순위는 Groq `openai/gpt-oss-120b`다. 모델명은 2026-11-13 문서 기준이다.
- 한도 초과(429)가 난 제공자는 60초 동안 건너뛴다.
- 키는 환경변수 `GEMINI_API_KEY`, `GROQ_API_KEY`에서 읽는다. 하나만 있어도 돌아간다.
- 이 대화에서 먼저 만든 시험용 `sogaeting.py`의 호출 부분이 위 동작을 이미 하고 있고 가짜 응답 테스트를 통과했다. 그대로 가져다 쓴다. 실제 API로는 아직 불러 보지 못했다.
- 호출 예산: 정상일 때 한 판 7회. 하루 500회 한도면 약 70판, 2인 1팀 기준 약 35팀이다. 2순위 제공자의 한도는 여기에 넣지 않았다.

### 5.14 데이터 파일

레포를 다른 단계와 같이 쓰므로 이 파트는 `sogaeting/` 폴더 하나 안에 둔다. 그 안에 캐릭터, 사건 카드, 선택지, 엔딩과 칭호, 금지어, 한 판의 순서를 각각 JSON 파일로 둔다. 예시 캐릭터 "하늘" 하나를 넣어 두고, 실제 명단은 1단계에서 정해지는 대로 파일만 추가한다.

캐릭터 파일에 들어가는 것: 식별자, 이름, 별칭, 설정, 모드별 말투, 좋아하는 행동과 싫어하는 행동, 등장 대사, 대체 대사, 표정별 그림 경로(없어도 됨).

### 5.15 확인 방법

- 감독, 호감도 계산, 모드 전환, 엔딩과 칭호 판정, 배우 답 읽기는 가짜 배우를 끼워 자동 테스트한다. 무작위 뽑기는 씨앗값을 고정해 테스트한다.
- 실제 API와 화면 연출은 리허설 때 사람이 확인한다. 확인 항목은 구현 계획에 목록으로 넣는다.

## 6. 만드는 사람에게 맡기는 것

- `sogaeting/` 안의 파일 나누기와 이름
- 벚꽃, 암전, 흔들림 같은 연출을 CSS로 구현하는 방법
- 사건 카드와 선택지의 대사 문구 초안 (팀이 나중에 데이터 파일에서 고친다)
- 금지어 목록의 구체적인 단어
- 포트 번호, 실행 명령
- 효과음과 BGM. 파일이 있으면 틀고 없으면 조용히 넘어가게만 만든다

## 7. 작성자가 정한 것 (승인할 때 봐 주세요)

1. 웃음은 대본이 책임지고 모델은 즉흥 반응만 맡는다 (4절 B안).
2. 화면은 웹 브라우저, 서버는 설치가 필요 없는 Python 표준 라이브러리.
3. 한 판은 입력 9번(글 7, 버튼 2), 모델 호출 7회.
4. 겉말과 속마음을 따로 보여 준다.
5. 팝업 숫자는 장식이고 실제 호감도는 0-100으로 얌전하게 움직인다.
6. 얀데레는 다른 캐릭터 이름을 치면 들어간다.
7. 엔딩 다섯 종류와 칭호 다섯 종류, 그리고 그 조건.
8. 처음 넣을 사건 카드 열 장.
9. 대화 원문은 저장하지 않는다.
10. 2단계는 혼자 돌아가는 프로그램으로 만들고, 다른 단계의 사건에 반응하는 기능은 넣지 않는다.

## 8. 팀에 확인이 필요하지만 진행을 막지 않는 것

- 캐릭터 명단, 설정, 그림. 정해지기 전까지 예시 캐릭터로 만든다.
- 3단계가 호감도를 어떻게 읽어 갈지. 일단 결과 파일로 남긴다.
- 무료 한도가 모자랄 때 유료로 바꿀지.
- 효과음과 BGM 파일을 누가 구할지.
