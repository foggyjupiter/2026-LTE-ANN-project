# 소개팅 (AI 연애 시뮬레이터 2단계)

캐릭터를 고르고 한 판(등장, 답 10번, 엔딩)을 하는 프로그램이다. 화면은 세 가지다: 부스용 Ren'Py 화면, 브라우저 화면, 터미널. 서버와 엔진은 설치할 패키지가 없다. Python 3.10 이상이면 된다.

설계는 `docs/superpowers/specs/2026-11-13-sogaeting-design.md`, 캐릭터는 `docs/characters.md`에 있다.

## 부스에서 켜기 (Ren'Py 화면)

레포 맨 위의 `run_booth.bat`(윈도우)이나 `run_booth.sh`(맥, 리눅스)를 더블클릭한다. 서버와 게임이 함께 켜지고, 게임을 끄면 서버도 꺼진다. Ren'Py SDK 8.5.3이 있어야 한다. 설치와 문제 해결은 `renpy/README.md`에 있다.

```
python run_booth.py           # 실제 모델
python run_booth.py --fake    # 키 없이 가짜 모델로 시연
```

윈도우에서는 PowerShell 한 줄로 받고 켤 수도 있다. `renpy/README.md`의 "윈도우에서 한 줄로 켜기"를 본다.

Ren'Py는 화면만 그린다. 대화는 전부 아래의 서버가 맡는다.

## 브라우저로 하기

레포 맨 위 폴더에서 실행한다. 윈도우에서는 `python3` 대신 `python`을 쓴다.

```
python3 -m sogaeting.server --fake   # 키 없이 가짜 모델로 시연
python3 -m sogaeting.server          # 실제 모델
```

터미널에 찍힌 주소(기본 `http://127.0.0.1:8000/`)를 크롬으로 열고 전체 화면(F11)으로 둔다. 끌 때는 터미널에서 Ctrl-C를 누른다.

- 캐릭터를 바로 지정해서 열기: `http://127.0.0.1:8000/?character=mistral`
- 다른 포트: `--port 8080`
- 판이 끝난 뒤 결과 읽기(3단계용): `GET /api/session/<판 id>/result`, 또는 `results/` 폴더의 파일
- 3분 동안 입력이 없으면 판을 버리고 첫 화면으로 돌아간다.
- 연출만 따로 보기: `http://127.0.0.1:8000/fx-demo.html`

캐릭터 그림을 `sogaeting/web/assets/characters/<캐릭터 id>/<표정>.png`로 넣으면 픽셀 얼굴 대신 그 그림이 나온다. 표정은 `neutral`, `smile`, `blush`, `pout`, `shock`, `dark`다.

## 터미널로 하기

```
python3 -m sogaeting --fake          # 키 없이 가짜 모델로 시연
python3 -m sogaeting                 # 실제 모델. 캐릭터를 번호로 고른다
python3 -m sogaeting mistral            # 캐릭터를 바로 지정
```

캐릭터 id: `astra`(아스트라), `gemma`(젬마), `sora`(소라), `nova`(노바), `mistral`(미스트랄), `haiku`(하이쿠)

진행 중에 1, 2, 3을 치면 선택지를 고르고, 다른 글을 치면 그대로 입력된다. `q`를 치면 곧장 엔딩으로 간다.

## 실제 모델 연결

레포 맨 위 폴더에 `.env` 파일을 만들고 키를 적는다. 이 파일은 `.gitignore`에 들어 있어서 커밋되지 않는다. 키를 코드나 다른 파일에 적지 않는다.

```
GEMINI_API_KEY=여기에_키
GROQ_API_KEY=있으면_적기
```

Gemini 키만 있어도 된다. 호출 순서와 모델명은 `sogaeting/llm.py`의 `PROVIDERS`에 있다. 터미널에 `[gemini-flash-lite] HTTP 400`이나 `401`이 찍히면 모델명이나 키가 틀린 것이다.

- 예비 키: `GEMINI_API_KEY=키1,키2,키3`처럼 쉼표로 이어 적으면 한도(429)가 찬 키를 건너뛰고 다음 키를 쓴다. 한도는 키가 아니라 프로젝트마다 잡히므로 같은 프로젝트의 키를 여러 개 적어도 소용이 없다. AI Studio의 API 키 화면에서 프로젝트를 새로 만들고 그 프로젝트로 키를 받는다(구글 문서: "Rate limits are applied per project, not per API key"). 계정은 같아도 된다고 문서에 적혀 있지만 계정 하나에 만들 수 있는 프로젝트 수에는 한도가 있다.
- 지금 쓰는 모델은 `gemini-3.5-flash-lite`, 예비로 `gemini-3.1-flash-lite`와 `gemini-3-flash-preview`, Groq 키가 있으면 `openai/gpt-oss-120b`다. 무료 한도는 모델마다 따로라서 예비 모델이 많을수록 하루에 더 많이 부를 수 있다. 2026-11-13에 무료 등급 키로 재 보니 설계의 주 모델 `gemini-3.8-flash`는 15번 중 한 번도 답하지 못해서(과부하) 기본 목록에서 뺐다.
- **유료 등급(Tier 1):** AI Studio에서 그 프로젝트에 결제 계정을 연결하면 바로 올라가고 하루 한도가 크게 는다(정확한 값은 AI Studio의 프로젝트 화면에 나온다). 2026-11-13 요금표 기준 `gemini-3.5-flash-lite`는 입력 100만 토큰에 0.30달러, 출력 100만 토큰에 2.50달러다. 한 판(답 10번)에 보내는 글이 약 10만 자라서 한 판에 몇십 원, 300판에 1-2만 원쯤으로 어림한다(한국어가 토큰 몇 개로 세어지는지는 재 보지 않았다). 결제 계정에는 예산 알림을 걸어 둔다.
- 유료 키로 `gemini-3.8-flash`를 쓰려면 `.env`에 `GEMINI_MAIN_MODEL=gemini-3.8-flash` 한 줄을 적는다. 그 모델을 맨 먼저 부른다. 적은 뒤에는 아래 시험 도구로 응답 시간을 잰다.
- 한 턴에 15초 안에 답이 없으면 캐릭터별 대체 대사가 나간다(`llm.py`의 `TURN_BUDGET_SEC`). 10초일 때 구글이 느린 밤에는 판마다 두세 번 그랬다(2026-11-13, 589답 가운데 61번). 대체 대사의 대부분은 검열이 아니라 이 응답 없음이다. 느린 요청은 5초에 끊고 예비 모델을 부른 뒤, 시간이 남으면 주 모델을 다시 부른다.
- 수위: 고등학생이 하는 게임으로 보고 심한 것만 막는다(2026-11-13). 금지어(`data/banned.json`)는 심한 욕설과 패드립, 노골적인 성적 표현, 성범죄, 죽이겠다는 위협, 자해와 자살 암시만 남겼다. 지시문은 손잡기, 어깨에 기대기, 머리 쓰다듬기, 짧게 안기까지와 또래 말투를 허용한다. 캐릭터가 고등학생이라 성적인 표현과 입맞춤은 하지 않고, 키스나 야한 이야기를 들으면 당황해서 되받으며 거절한다(점수는 0 이하).
- **무료 등급에는 하루 한도가 있다.** 2026-11-13에 확인한 값은 모델마다 프로젝트당 하루 500번이다. 한 판에 12-13번 부르므로 키 하나로 주 모델 약 40판이다. 예비 모델은 한도가 따로라서 그만큼 더 할 수 있다. 미국 서부 시간 자정(한국 시간 오후 5시)에 풀린다. 축제 날 판이 더 많을 것 같으면 다른 프로젝트에서 만든 키를 예비 키로 적거나 유료 등급을 쓴다. 한도에 닿은 날에는 요청이 통과했다 막혔다 하고, 막히면 예비 모델이 답한다. 예비 모델도 바쁘면 괄호 속 행동(대체 대사)이 나간다. 서버 창에 `하루 한도 초과`가 자주 찍히면 키를 늘린다.

키가 없거나 인터넷이 끊기면 캐릭터별 대체 대사로 엔딩까지 간다.

캐릭터가 괄호 속 행동(대체 대사)만 하면 `python3 -m sogaeting.check` 를 실행한다. 키마다, 모델마다 짧은 요청을 한 번씩 보내고 하루 한도, 틀린 키, 구글 과부하, 인터넷 문제 가운데 무엇인지 알려 준다. 키 값은 찍지 않는다. `.env` 를 메모장이나 PowerShell로 저장해서 BOM이 붙어도 읽는다. 윈도우 환경변수에 같은 이름의 키가 있으면 그쪽이 이기므로, 점검 도구가 그것도 알려 준다.

### 실제 모델로 한 판씩 돌려 보기

```
python3 -m sogaeting.playtest               # 여섯 캐릭터를 정해 둔 각본으로 한 판씩
python3 -m sogaeting.playtest --only mistral   # 한 명만
python3 -m sogaeting.playtest --fake        # 키 없이
```

`results/playtest/` 에 캐릭터별 대화 전문과 요약(응답 시간, 대체 대사 횟수, 답한 모델)이 생긴다. 리허설 때 이것으로 말맛과 속도를 본다.

## 구조

| 파일 | 하는 일 |
|---|---|
| `director.py` | 진행자. 한 판의 순서, 뇌절 강도, 씨앗, 연출 거르기, 호감도, 엔딩 등급 |
| `actor.py` | 배우. 모델에 보낼 지시문을 만들고 모델의 답(JSON)을 읽는다. 답에 캐릭터가 모르는 말(AI, 프롬프트), 아슬아슬한 말의 되받기, 대사 예시 베끼기, 너무 긴 겉말(하이쿠)이 있으면 한 번 고쳐 쓰게 한다 |
| `gimmicks.py` | 캐릭터별 고유 장치. 소라는 장치가 없다(들린 말 가리기를 뺐다) |
| `safety.py` | 입력 다듬기(100자), 금지어 검사 |
| `content.py` | `data/`의 JSON을 읽는다 |
| `llm.py` | 모델 호출. 제공자를 차례로 시도한다 |
| `fake_llm.py` | 키 없이 돌려 볼 때 쓰는 가짜 모델 |
| `cli.py` | 터미널 실행기 |
| `server.py` | 로컬 서버. 엔진을 JSON API로 감싸고 `web/`의 파일을 내준다 |
| `playtest.py` | 실제 모델로 정해 둔 각본을 돌려 대화 전문과 응답 시간을 남긴다 |
| `../run_booth.py` | 서버와 Ren'Py 게임을 함께 켠다 |
| `../renpy/` | 부스용 Ren'Py 화면(고르기, 대화, 엔딩, 연출 15가지). 서버를 HTTP로 부른다 |
| `web/app.js`, `style.css`, `index.html` | 화면 세 개(고르기, 대화, 엔딩) |
| `web/fx.js`, `fx.css` | 화면 연출 15가지 |

## 내용 고치기

코드를 건드리지 않고 `sogaeting/data/`의 JSON만 고치면 된다.

- 캐릭터의 말투, 반응, 대체 대사: `data/characters/<id>.json`
- 씨앗 낱말(학교 드립은 여기에 추가): `data/seeds.json`
- 호감도: 50점에서 시작한다. 모델이 답마다 주인공의 말만 보고 delta(-2에서 2)를 매기고, 진행자가 `director.py`의 `POINTS`로 점수를 움직인다. 오르는 쪽은 작고(+1은 2점, +2는 캐릭터마다 5-8점) 내리는 쪽은 크다(-1은 -5점, -2는 -10점). +2의 점수는 캐릭터 데이터의 `hit_points`이고, 속마음 힌트가 잘 보이는 캐릭터일수록 낮다: 젬마, 소라 5점, 아스트라, 노바 6점, 미스트랄 7점, 하이쿠 8점(기본값). Claude가 직접 해 본 6판이 +8일 때 넷이 100점이라 2026-11-14에 나눴다. 지금 값이면 대성공(85)에 바라던 말이 3-5번, 100점에 5-10번 필요하다.
  - 설렘: 모델은 delta와 함께 그 말에 캐릭터가 얼마나 설렜는지(`strength`, 0-100, 보통 50)를 낸다. 진행자는 위 점수에 설렘에 따라 고르게 바뀌는 값을 곱한다(`director.py`의 `strength_scale`): 다정한 말과 내리는 말은 0.6-1.4배(50이면 그대로), 바라던 말은 0.4-1.1배(50이면 0.75배). 바람을 짚기만 해서는 크게 오르지 않고 얼마나 설레게 했는지에 따라 달라진다. 지시문은 짚은 것(delta)과 설렘을 따로 매기게 하고 기준을 적었다(낱말만 꺼낸 말 10-20, 건성인 말 30-40, 다정한 말 50, 구체적이고 이 캐릭터만을 향한 말 70-80, 숨이 멎을 말 90-100, 사이의 값도 쓴다). 바라던 말이라도 글자가 10개 이하이면("필통 예쁘네") 설렘을 30까지로 두고(`SHORT_HIT_LETTERS`), 선택지를 고른 말은 50까지다. 고쳐 쓴 답도 처음 답의 설렘을 쓴다. 호감도는 소수 한 자리로 움직인다.
  - 점수가 높을수록 덜 오른다: 오르는 점수에 `max(0.3, (100 - 지금 점수) / 40)`를 곱한다(`SLOWDOWN_FROM` 60, `SLOWDOWN_FLOOR` 0.3). 60점까지는 그대로, 80점이면 절반, 88점부터는 0.3배다. 내리는 점수는 그대로다. 100점은 거의 닿지 않아 순위표에 공동 1위가 잘 안 생기고, 지금 점수에 따라 오르는 폭이 달라져 점수가 더 고르게 퍼진다.
  - 내력(2026-11-14): 처음에는 칸(delta)만으로 움직여서 다정하게 한 실전 시험 6판 가운데 3판이 똑같이 66점이었다. 설렘을 1-5로 더했다가 "아직 이산적"이라는 의견에 0-100으로 바꿨다. 끝값은 1-5 때 실전 시험으로 맞췄다(바라던 말의 5를 1.25배로 두면 속마음을 읽는 참가자가 평균 89.0점이라 1.1배로 낮춤). Claude가 속마음을 읽고 한 6판이 평균 93점, 3판이 100점이라 높을수록 덜 오르게 했다(같은 대화를 다시 매기면 평균 84.7점, 100점 0판, 다정한 참가자는 66.9 → 66.4점).
  - 바람: 캐릭터는 답마다 주인공이 알아주기를 바라는 작은 것 하나를 화면에 안 나오는 `wish` 칸에 적고, 그 화제 낱말을 속마음에 흘린다("필통 예쁘다고 말해주면 좋겠다"). +2는 참가자가 최근 두 답의 바람을 짚었을 때만 나온다. 모델이 2를 줘도 참가자의 말에 바람의 낱말이 없으면 진행자가 +1로 줄인다(`actor.wish_touched`). 바람이 화면 글에 안 보이면 한 번 고쳐 쓰게 하고, 세 답 연달아 같은 바람이면 바꾸게 한다.
  - 진행자가 덧붙이는 규칙: 두 글자 이하의 단답("응", "별로")은 올리지 않는다, 선택지를 그대로 고른 말은 +1까지다.
  - 그래서 다정한 말만 이어 가면 70점 언저리(성공)에서 멈추고, 대성공(85점)에는 바람을 서너 번 짚어야 한다. 시험 기록(실제 모델): 착한 각본 60-74점, 속마음을 읽고 답하는 참가자(모델이 대신 함, `playtest.py --attentive`) 아스트라 85-91, 젬마 98, 노바 82점.
- 한 판의 길이와 강도: `data/schedule.json`. 지금은 답 10번이고 3, 6, 8번째 답에 사건이 끼어든다. 마지막 두 사건(6, 8번째)은 손잡기, 어깨에 기대기, 짧게 안기 같은 순간의 계기가 되는 사건(`data/seeds.json`의 `event_hints`: 천둥 번개, 점심시간 인파, 계단 헛디딤, 오후의 졸음, 손난로 하나, 흩날리는 벚꽃잎, 정전, 소나기와 우산 하나, 같은 책에 손이 닿음)에서 고른다. 마지막 사건에서는 둘이 실제로 닿는 장면(캐릭터가 하는 일로)까지 쓰게 하고, 지문과 겉말에 그런 장면이 없으면 한 번 고쳐 쓰게 한다(`actor.has_touch`). 사용자가 그런 순간이 거의 늘 나오기를 바라서 2026-11-14에 바꿨다. 그 전에는 "계기가 될 수 있다"로만 적어서, 실전 기록 24판에서 그런 사건 답의 6할 남짓(글자 찾기로 어림)에서만 닿았다. 호감도가 낮으면 우연히 닿았다가 떨어지는 정도로 쓰게 한다. 답 수를 바꾸면 함께 맞출 것: 점수표 `director.py`의 `POINTS`, 젬마가 말을 꺼내는 답 `gimmicks.py`의 `QUOTE_TURNS`, Ren'Py의 `sg_stage_big_up`, `sg_score_big_up`(+2의 가장 작은 점수), 시험 각본 `playtest.py`. 테스트가 어긋난 곳을 알려 준다.
- 금지어: `data/banned.json`

## 이야기 모드 (실험)

친구의 의견("노잼, Zeta처럼 대화가 길었으면")으로 만든 실험이다. 기본은 꺼져 있다. 환경변수 `SOGAETING_STORY=1` 을 주거나 `python3 -m sogaeting.playtest --story` 로 돌린다.

- 답이 길다: 지문 2-3문장, 겉말 3-5문장(하이쿠처럼 겉말 길이가 정해진 캐릭터는 그대로).
- 캐릭터가 이야기를 끌고 간다: 답마다 제안, 장소 옮기기, 작은 비밀, 주인공에게만 할 질문 가운데 하나를 하고, 겉말의 마지막 문장을 주인공이 받아칠 거리로 끝낸다. 둘이 함께 다른 곳으로 옮겨 갈 수 있다.
- 한 판이 답 12번이고 답마다 이야기 단계가 있다(`data/schedule_story.json`): 첫 만남, 함께 움직이기, 작은 비밀, 사건, 편해짐, 작은 엇갈림, 사건으로 풀림, 솔직한 말, 다음 약속, 가까워지는 순간(사건), 결정적 순간, 헤어짐.
- 점수: 답마다 움직이는 점수에 0.75를 곱한다(`director.py`의 `STORY_POINTS_SCALE`). 실전 시험(2026-11-14, 평범한 참가자 역할, 3캐릭터씩)에서 지금 방식 평균 73.9점, 이야기 모드 82.8점이었고 오른 몫의 비가 0.73이었다. 3판씩이라 어림값이다.
- 글 길이: 같은 시험에서 지문은 평균 43-50자에서 70-97자, 겉말은 60-71자에서 77-113자로 늘었다.
- 화면: 긴 지문과 대사는 Ren'Py 대화창에서 문장 단위로 여러 쪽으로 나뉜다(대사는 글자 24에 세 줄, 지문은 22). 대사창 오른쪽 아래에 "1/2"처럼 쪽이 적히고, 선택지가 뜰 때는 마지막 쪽이 남는다.
- 켜기: 서버는 `python3 -m sogaeting.server --story`(가짜 모델은 `--fake --story`).
- 아직 맞추지 않은 것: 젬마가 말을 꺼내는 답(`QUOTE_TURNS`, 지금은 3, 6, 10번째), 실행기(`run_booth.py`)에서 켜는 옵션.
- 시험용 참가자: `--casual` 은 속마음을 노리지 않고 상대의 말에 자연스럽게 반응하는 참가자 역할을 모델이 한다.

## 결과

판이 끝나면 `results/` 폴더에 캐릭터, 호감도(0-100, 소수 한 자리), 등급, 엔딩 이름, 칭호, 끝난 시각이 JSON으로 저장된다. 대화 원문은 저장하지 않는다. 가짜 모델(`--fake`)로 돈 판에는 `"fake": true` 가 붙는다.

## 순위표

상품을 주려고 만든 순위표다. 엔딩 화면의 "순위표 등록"으로 학번과 이름을 남기면 그 판의 결과 파일에 `student_id`, `player_name` 이 적히고 오늘의 순위표가 나온다. 첫 화면 오른쪽 위의 "오늘의 순위"로도 볼 수 있다(`ranking.py`).

- API: `POST /api/session/<판 id>/rank` 에 `{"student_id": "20312", "name": "김민수"}` (엔딩을 본 판만, 다시 보내면 고쳐 적는다), `GET /api/ranking` 은 오늘의 순위표.
- 한 학번은 한 줄이다. 여러 판을 했으면 가장 높은 호감도가 들어간다. 같은 호감도면 같은 등수다(1, 2, 2, 4). 같은 등수 안에서는 그 기록을 먼저 낸 사람이 위에 온다. 위에서 10줄을 보여 주고, 내 학번이 그 밖이면 한 줄 더 보여 준다.
- 화면에는 학번과, 가운데 글자를 가린 이름이 나간다(김민수는 김*수). 파일에는 이름이 다 남는다. 화면에도 다 보이게 하려면 `ranking.py`의 `SHOW_FULL_NAME` 을 `True` 로 바꾼다.
- 순위는 결과 폴더의 파일에서 매번 다시 매긴다. 서버를 다시 켜도 남는다. 오늘(서버 컴퓨터의 날짜) 끝난 판만 들어간다. 날을 넘기면 새 순위표가 된다.
- 실제 모델 서버의 순위표에는 가짜 모델 판이 안 들어간다(가짜 모델 서버에서는 반대로 가짜 판만 나온다).
- 학번은 숫자 4-10자리(공백과 하이픈은 지운다), 이름은 한글이나 영문 2-12자다. 대사 금지어(`data/banned.json`)와 순위표용 금지어(`ranking.py`의 `NAME_EXTRA_BANNED`)가 든 이름은 거절한다. 학번 자릿수는 학교 형식을 몰라서 넉넉히 받았다(`STUDENT_ID_RE`).
- 학번과 이름은 `results/` 에만 남는다. 이 폴더는 `.gitignore` 에 있어서 레포에 올라가지 않는다. 대화 내용은 바깥 모델에 가므로 첫 화면에 "대화에는 실명과 학번을 적지 마세요"라고 적어 둔다.
- 순위를 지우려면 `results/` 의 파일을 지우거나 옮긴다. 리허설 판이 섞이지 않게 행사 전에 비워 둔다. 상품을 다 준 뒤에는 학번과 이름이 든 파일을 지운다.
